A significant release with improvements all throughout the application. With the addition of the scroll, neck, and string setup panels, CremonaCad now can create a full set of traditional templates for the making of violin family instruments. Other changes include: 

- **Modification Toolbox** - A new toolbox has been added with a variety of modification tools which allow you to manipulate objects more like a traditional CAD program. 
- **Copy Paste** - The canvas is much more interactable. All objects drawn on the canvas can be selected, copied, pasted, duplicated and exported. 
- **More Tools** - Many more tools have been added, including tools for drawing custom Catenary, Cycloids and Batten curves. 
- **Improved Documentation** - Documentation has moved to a wiki based article system to improve clarity and hopefully make the application easier to use.
- **Improved Errors** - Error messages have been improved so they are less interfearing to the user. Shapes are now rendered on the canvas where possible to indicate which fields are creating uncalculable goemetry, and what you can do to fix them.
- **Bundled SVG exports** — Much like the PDF export, you may now export all profiles and templates in a single SVG file
- **XY Keyboard Inputs** - When selecting XY coordinate textboxes, you may now use the arrow keys to move the point freely on the canvas. This should incease the speed for placing points, as they no longer require that the user rotate between input boxes. 
- **F-hole Surface Compensation** - Drawing an F-hole against a 2D image introduces distortion problems we placing the template back against a surface. The export panel now supports an f-hole template which attempts to compensate for this. 
- **F-hole Notches** - Notches are now added to f-holes based on stem location. The position of the outer notch is based on a method published by David Sora.
- **Profile Rendering** - Instrument profiles remain rendered as you go back and forth in your design. This should give a more coherent view of your changes. Instrument profiles always render in the same place.
- **Arcs as Spans** - Where sensible, arc start and endpoints are no longer explicitly defined, rather you only need to type in the span of your arc in degrees. 
- **Cleaner Code** - A significant rewrite of the underlyind data models was done. Inpout parameters were completely seperated from calculated geometry, creating much better seperation of concerns between UI elements and their effected data. Panels now follow much more consistent architecture and spread accross helper files has been reduced. All this should aid future development.
